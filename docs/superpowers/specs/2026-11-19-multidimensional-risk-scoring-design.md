# 多维风险标签与评分设计

## 意图

在现有“顺日线趋势 + 回调转强/平台突破 + 盘前价格确认”扫描器上，补充市场环境、基本面、事件/消息面和期权可交易性。新增维度不改变技术信号的入选资格，只用于帮助用户理解候选标的的质量与风险，避免因为条件叠加过多而长期没有候选。

## 目标

- 继续由现有技术规则决定候选标的。
- 为每个候选生成 0–100 综合观察分、五个分项分数、数据完整度和风险标签。
- 免费数据源不可用时按维度降级为“数据暂缺”，仍完成报告和企业微信推送。
- 报告保持适合手机阅读，并明确区分“技术触发”“评分”“风险标签”。
- 数据源采用可插拔接口，未来接入付费 API 时不修改评分和报告模型。

## 非目标

- 不自动下单，不选择具体期权合约，不计算预期收益。
- 不把综合分解释为胜率或涨跌预测。
- 第一阶段不做大模型新闻摘要，不抓取需要登录或付费墙的内容。
- 第一阶段不扩大当前股票池。
- 新维度不作为硬过滤条件。

## 约束与反目标

- GitHub Actions 必须在盘前有限时间内完成；单一外部接口不能拖垮整次扫描。
- 免费数据可能缺失、延迟或字段口径变化，禁止把缺失数据当成负面数据扣分。
- 同一事实不能重复加减分，例如财报临近不能同时在事件分和消息分重复惩罚。
- 综合分不能掩盖高风险事件；红色风险标签始终独立展示。
- 报告不能因内容过多退化成难以阅读的长文本。

## 方案比较

### 方案一：完全依赖免费数据

直接在现有 `YahooMarketData` 中加入所有取数逻辑。实现快、成本低，但数据源耦合严重，Yahoo 字段变化会同时影响多个维度，后续替换困难。

### 方案二：直接接入付费数据 API

新闻、事件和期权数据更稳定，但当前没有 API 订阅和密钥，会增加费用、密钥管理与供应商锁定。

### 方案三：可插拔渐进版（已选择）

先使用免费数据实现，每个维度通过独立 provider 接口返回标准模型；评分器和报告只依赖标准模型。未来可单独替换为付费 provider。取数失败以缺失状态返回，不阻断扫描。

## 总体流程

1. 使用原有日线规则生成候选。
2. 使用原有盘前报价标记“允许关注/不追/失效/异常”。
3. 只对候选标的并发采集四类补充数据：市场环境、基本面、事件消息、期权链。
4. 将原技术信号和补充数据输入统一评分器。
5. 生成综合分、分项分、风险标签、数据完整度和简短依据。
6. 渲染为企业微信图片；任何补充维度失败均降级，不影响主流程。

## 标准数据模型

新增不可变模型：

- `DimensionStatus`: `ok / partial / unavailable / error`。
- `Evidence`: 指标名、原始值、显示值、来源、采集时间。
- `DimensionScore`: 维度名、得分、满分、状态、依据、标签。
- `RiskTag`: 级别 `info / caution / high`、代码、短标题、说明。
- `CandidateAssessment`: 候选、综合分、五个分项、风险标签、数据完整度。

综合分仅累计状态为 `ok` 或 `partial` 的已知指标，并同时展示数据完整度。缺失维度的分数显示 `--`，不按零分处理。为了避免不同完整度的候选被误比较，报告按原技术排序为主，综合分只作辅助展示。

## 五个评分维度

### 1. 技术结构：30 分

复用已有可靠数据，不新增网络请求：

- 趋势合格（收盘在 MA20 上方且 MA20 上升）：8 分。
- 收盘在 MA50 上方：4 分。
- MA20 在 MA50 上方：4 分。
- 近 10 日高低点结构抬升：4 分。
- 回调转强触发：5 分。
- 放量平台突破触发：5 分。

技术分用于描述形态质量，但候选资格仍由原逻辑决定。

### 2. 市场与行业环境：20 分

- SPY 日线趋势合格：5 分。
- QQQ 日线趋势合格：5 分。
- 标的 20 日收益相对 SPY 为正：4 分。
- 标的 20 日收益相对 QQQ 为正：3 分。
- 标的 20 日实现波动率未处于自身近半年极端区间：3 分。

第一阶段不引入行业 ETF 映射，避免错误行业归类；接口为后续行业强弱预留字段。

### 3. 基本面质量：20 分

从免费公司信息/财务字段中读取，按可得项计分：

- 营收同比增长为正：5 分。
- 每股收益或净利润同比增长为正：5 分。
- 自由现金流为正：4 分。
- 净利润率为正：3 分。
- 负债权益比不过度异常：3 分。

SPY、QQQ 不计算公司基本面，该维度显示“不适用”。估值不直接奖励低 PE，避免成长股与成熟公司口径失真；估值只作为信息证据展示。

### 4. 消息与事件风险：15 分

这是“风险清洁度”分，不是新闻看多分：

- 未来 7 个自然日无财报：6 分；3 日内财报生成高风险标签。
- 当日无 FOMC、CPI、非农等主要宏观事件：4 分。
- 最近 24 小时无明确高影响负面标题：3 分。
- 新闻数据新鲜且来源可识别：2 分。

免费新闻只做保守关键词分类并显示原始标题，不用大模型推断。无法可靠判断时标记“消息数据暂缺”，不扣分。

### 5. 期权可交易性：15 分

第一阶段选取距离到期 14–45 天、接近平值的代表性看涨/看跌合约进行市场质量评估，而不是推荐合约：

- 存在合适到期日和接近平值合约：3 分。
- 买卖价差/中间价不超过 10%：4 分。
- 单合约未平仓量达到 500：3 分。
- 单合约当日成交量达到 100：2 分。
- 隐含波动率可取得且未出现明显异常值：3 分。

免费数据无法稳定计算历史 IV Rank，因此第一阶段展示当前 IV，不伪造 IV Rank。价差超过 15%、无报价或流动性过低生成风险标签。

## 风险标签规则

标签独立于综合分，优先级从高到低展示：

- 高风险：`3天内财报`、`重大宏观事件日`、`盘前信号失效`、`期权无有效报价`。
- 谨慎：`盘前跳空偏高`、`期权价差偏大`、`期权流动性偏低`、`波动率异常`、`近期负面标题`。
- 信息：`基本面数据不完整`、`消息数据暂缺`、`期权数据暂缺`。

标签必须带短依据，例如“财报预计 2026-11-21（盘后）”，不能只显示结论。

## 数据提供者与容错

定义四个 provider 协议：

- `MarketContextProvider`
- `FundamentalsProvider`
- `EventNewsProvider`
- `OptionsProvider`

首个实现继续使用 `yfinance` 和 NYSE 日历；宏观日历采用仓库内可维护的结构化日历文件，避免依赖不稳定网页抓取。每个 provider 设独立超时和有限重试，并捕获为维度级错误。日志只记录标的、provider、错误类型，不记录 Webhook 或其他敏感配置。

只对技术入选候选取补充数据。候选数量少时使用受限并发，默认最多 4 个工作线程，防止免费接口限流。

## 报告设计

企业微信图片改为两级信息：

### 顶部摘要

- 交易日、纽约开盘时间。
- SPY/QQQ 市场状态。
- 候选数量、数据异常数量。
- 免责声明：“评分是信息完整度下的观察分，不代表胜率”。

### 候选卡片

- 第一行：代码、技术触发、综合观察分。
- 第二行：盘前状态、盘前涨跌、参考失效位。
- 第三行：五项分数，用紧凑条形或 `技术 26/30 · 环境 14/20 · …` 表示。
- 第四行：最多三个最高优先级风险标签。
- 第五行：一条核心依据，例如“20日相对 SPY +6.2%；财报还有 18 天；期权价差 7.4%”。
- 数据缺失的维度显示 `--`，同时显示完整度，例如 `数据完整度 82%`。

如果候选较多，自动增加图片高度；继续保持单张图片小于企业微信 2 MB。Markdown dry-run 输出同样字段，用于测试和排障。

## 配置

在 `Settings` 中新增阈值并提供保守默认值：财报警戒天数、期权到期范围、最大价差、最低成交量、最低未平仓量、provider 超时、并发数。第一阶段不要求新增 Secret；未来付费 provider 通过独立环境变量启用。

## 测试与验收

- 各 provider 使用固定响应测试正常、部分缺失、超时和异常。
- 评分器验证边界、缺失不按零分、总分不超过 100、标签优先级和去重。
- 主流程验证补充 provider 全部失败时仍推送原技术报告。
- 图片和 Markdown 验证五项分数、风险标签、完整度和免责声明。
- GitHub Actions 运行完整测试并完成一次真实企业微信测试发送。
- 验收标准：原技术候选集合不因新增维度改变；报告能解释分数来源；任一补充数据源失败不导致整次任务失败。

## 实施分期

第一阶段一次完成模型、provider 接口、技术/环境/基本面/事件/期权评分、风险标签和新版报告；对免费源确实无法可靠提供的字段明确显示暂缺。第二阶段在有付费 API 后替换单个 provider，并补充行业强弱与可靠的历史 IV Rank。
